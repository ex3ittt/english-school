# Онлайн-школа английского: кабинет ученика и админ-панель

Next.js 16 (App Router) + TypeScript, PostgreSQL + Prisma 7, собственная авторизация,
видео в S3-совместимом хранилище (Supabase Storage / Cloudflare R2 / AWS S3) по временным
подписанным ссылкам. Стили — CSS Modules со своей темой, без UI-китов.

## Что внутри

**Ученик**
- `/login` — вход по email и паролю, «Забыли пароль?» → письмо со ссылкой (`/forgot`, `/reset`). Регистрации нет.
- `/courses` — полка: основной курс крупно слева с прогрессом, справа обложки остальных курсов; недоступные приглушены, с замком.
- `/course/[id]` — главная курса: следующий урок, прогресс, программа по неделям.
- `/course/[id]/materials` — все файлы из открытых недель.
- `/course/[id]/week/[n]?day=1..7` — вкладки Пн–Вс, выбор преподавателя (запоминается), видео урока, блоки (видео / текст / файл), кнопка «Урок просмотрен».
- `/profile` — имя, email, смена пароля, выход.

**Администратор** (`/admin`, отдельный вход `/admin/login`)
- Обзор: сколько учеников, кто заходил, последние просмотры, кто давно не заходил, средний прогресс по курсам.
- Ученики: создать (пароль генерируется и показывается один раз), изменить, заблокировать, новый пароль или ссылка на почту, записать на курс, куратор и время занятий, дата старта, ручное открытие и закрытие недель, прогресс.
- Курсы: создание, обложка, уровень, публикация, «основной курс», автооткрытие недель, порядок на полке перетаскиванием.
- Недели → дни (Пн–Вс создаются автоматически) → уроки, порядок уроков перетаскиванием.
- Урок: видео от каждого преподавателя (загрузка файла или ссылка Vimeo / Kinescope), блоки с перетаскиванием.
- Преподаватели: имя, фото, описание, порядок вкладок.
- Загрузка видео: прямо из браузера в хранилище, с полосой прогресса, превью файла и автоматическим кадром-обложкой.

## Как устроена защита

- Сессии хранятся в БД (в cookie `httpOnly` только случайный токен, в таблице — его SHA-256). Пароли — scrypt.
- Роль проверяется на сервере в каждом layout, странице, server action и API админки (`requireAdmin` / `assertAdmin`), а не только скрытием кнопок. `src/proxy.ts` лишь быстро отправляет на вход тех, у кого нет cookie.
- Доступ к неделе считается на сервере (`src/lib/access.ts`): ручное решение админа → первая неделя с даты старта → автооткрытие через 7 дней после предыдущей. Закрытая неделя не отдаёт ни уроков, ни видео, ни файлов.
- Видео: плеер запрашивает `/api/media/video`. Сервер проверяет сессию, запись на курс и открытость недели и только после этого выдаёт ссылку на файл, которая живёт `MEDIA_URL_TTL` секунд (по умолчанию 15 минут). Если ссылка истекла во время просмотра, плеер берёт новую и продолжает с того же места. Ключи файлов случайные и в HTML не попадают.
- Файлы (PDF и др.) идут через `/api/media/file/[id]` с той же проверкой и ссылкой на 2 минуты.
- Блокировка ученика сразу завершает все его сессии.

> Честно о пределах: подписанные ссылки не дают раздавать видео по прямой ссылке и смотреть его без доступа,
> но полностью запретить запись экрана или скачивание через инструменты разработчика нельзя.
> Если нужна защита уровня DRM, используйте Kinescope (у него есть DRM и водяные знаки) — ссылка вставляется в уроке.

## Локальный запуск

Нужен Node.js 20+.

```bash
npm install
cp .env.example .env        # и поменяйте APP_SECRET
```

Postgres локально ставить не обязательно: используется встроенный PGlite (данные в папке `.pglite`).
`npm run dev` сам запускает его, если база ещё не работает. Первый раз создайте таблицы и тестовые данные —
для этого база должна быть запущена (в отдельном терминале `npm run db:local`, потом его можно закрыть):

```bash
npm run db:migrate
npm run db:seed
```

Дальше каждый раз достаточно одной команды:

```bash
npm run dev
```

Откройте http://localhost:3000.

| Роль | Email | Пароль |
| --- | --- | --- |
| Админ | `admin@school.local` | `admin12345` |
| Ученица (прошла 2,5 недели) | `anna@student.local` | `student12345` |
| Ученик (начал 2 дня назад, неделю 2 открыли вручную) | `ivan@student.local` | `student12345` |

Пароли задаются в `.env` (`SEED_*`). Повторный seed с очисткой базы: `SEED_RESET=1 npm run db:seed`.

Без SMTP письма восстановления пароля печатаются в консоль `npm run dev` — ссылку можно скопировать оттуда.

## Переменные окружения

| Переменная | Что это |
| --- | --- |
| `DATABASE_URL` | Строка подключения к Postgres. На Supabase — pooled (порт 6543, `?pgbouncer=true`). |
| `DIRECT_URL` | Прямое подключение (порт 5432) для миграций и seed. |
| `APP_URL` | Публичный адрес сайта, нужен для ссылок в письмах. |
| `APP_SECRET` | Длинная случайная строка (`openssl rand -base64 48`). |
| `STORAGE_DRIVER` | `local` (папка `./storage`, только для разработки) или `s3`. |
| `S3_ENDPOINT`, `S3_REGION`, `S3_BUCKET`, `S3_ACCESS_KEY_ID`, `S3_SECRET_ACCESS_KEY`, `S3_FORCE_PATH_STYLE` | Доступ к S3-совместимому хранилищу. |
| `MEDIA_URL_TTL` | Срок жизни ссылки на видео, в секундах (минимум 60). |
| `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASSWORD`, `MAIL_FROM` | Почта для восстановления пароля (подойдёт SMTP Resend, Яндекс 360, Unisender Go и т. п.). |
| `DATABASE_POOL_MAX` | Размер пула соединений на один инстанс (по умолчанию 5). |

## Деплой: Vercel + Supabase

### 1. Supabase

1. Создайте проект на supabase.com.
2. **Project Settings → Database → Connection string**:
   - *Transaction pooler* (порт 6543) → `DATABASE_URL`, добавьте в конец `?pgbouncer=true`;
   - *Session pooler / Direct* (порт 5432) → `DIRECT_URL`.
3. **Storage → New bucket**: например `school-media`, **Public выключен** (приватный).
4. **Storage → Settings → S3 Connection**: включите S3, скопируйте *Endpoint* и *Region*, создайте *Access key*.
   - `S3_ENDPOINT=https://<project-ref>.supabase.co/storage/v1/s3`
   - `S3_REGION=<регион проекта, например eu-central-1>`
   - `S3_BUCKET=school-media`, `S3_FORCE_PATH_STYLE=true`, `STORAGE_DRIVER=s3`
5. Лимит размера файла: **Storage → Settings → Upload file size limit** — увеличьте под ваши видео (на бесплатном тарифе максимум 50 МБ; для длинных уроков нужен Pro или R2).

### 2. Миграции и seed (один раз, со своего компьютера)

Пропишите в локальном `.env` адреса Supabase и `STORAGE_DRIVER=s3` с ключами, затем:

```bash
npm run db:migrate
npm run db:seed
```

Seed загрузит в бакет тестовое видео и PDF. Сразу поменяйте пароль админа в профиле, а тестовых учеников заблокируйте или удалите.

### 3. Vercel

1. Загрузите проект в GitHub и импортируйте его в Vercel (фреймворк определится сам, команда сборки — `npm run build`).
2. **Settings → Environment Variables**: добавьте все переменные из таблицы выше (`APP_URL` — ваш домен на Vercel или свой).
3. Deploy. Миграции при новых изменениях схемы запускайте `npm run db:migrate` (или добавьте её в Build Command: `prisma migrate deploy && npm run build`).

### Cloudflare R2 вместо Supabase Storage

`S3_ENDPOINT=https://<account-id>.r2.cloudflarestorage.com`, `S3_REGION=auto`, `S3_FORCE_PATH_STYLE=true`.
В настройках бакета добавьте CORS, иначе браузер не сможет загружать файлы:

```json
[{ "AllowedOrigins": ["https://ваш-домен"], "AllowedMethods": ["GET", "PUT"], "AllowedHeaders": ["content-type", "range"], "MaxAgeSeconds": 3600 }]
```

У AWS S3 CORS настраивается так же.

## Где что менять

- Название школы, буквы знака, почта поддержки: `src/config/brand.ts`.
- Цвета, фактуры и шрифты: `src/app/globals.css` (переменные в `:root`) и `src/app/layout.tsx`.
- Правила открытия недель: `computeWeekStates` в `src/lib/access.ts`.
- Схема БД: `prisma/schema.prisma`. После изменения: `npx prisma migrate dev --name <что-поменяли>` (на обычном Postgres).

## Структура

```
prisma/                 схема, миграции, seed и тестовые файлы
src/proxy.ts            быстрый редирект без cookie
src/lib/                БД, авторизация, доступ к неделям, хранилище, почта
src/app/(auth)/         вход, восстановление пароля
src/app/(student)/      полка, курс, неделя, материалы, профиль
src/app/admin/          админ-панель и её server actions
src/app/api/            видео, файлы, картинки, загрузка, локальное хранилище
src/components/         плеер, обложки, иконки, элементы админки
```

## Что стоит сделать перед большим запуском

- Ограничение частоты попыток входа (например, Upstash Rate Limit на `/login`) — сейчас от перебора защищает только медленный scrypt.
- Мониторинг ошибок (Sentry) и резервные копии БД (в Supabase включены на платных тарифах).
- Заменить плейсхолдеры бренда и тексты seed на свои.
